# Firstweeks Production Deployment Guide

## Prerequisites

### AWS Account Setup
1. **AWS Account** with BAA signed (required for HIPAA)
2. **IAM User/Role** with AdministratorAccess or least-privilege policy for Terraform
3. **S3 Bucket** for Terraform state (create manually first):
   ```bash
   aws s3 mb s3://firstweeks-terraform-state --region us-east-1
   aws s3api put-bucket-versioning --bucket firstweeks-terraform-state --versioning-configuration Status=Enabled
   aws s3api put-bucket-encryption --bucket firstweeks-terraform-state --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'
   ```
4. **DynamoDB Table** for state locking:
   ```bash
   aws dynamodb create-table \
     --table-name terraform-locks \
     --attribute-definitions AttributeName=LockID,AttributeType=S \
     --key-schema AttributeName=LockID,KeyType=HASH \
     --billing-mode PAY_PER_REQUEST \
     --region us-east-1
   ```

### Domain & Certificate
1. **Route 53 Hosted Zone** for `firstweeks.app`
2. **ACM Certificate** for `*.firstweeks.app` and `firstweeks.app` in `us-east-1` (required for CloudFront/ALB)

### Docker Images
1. **ECR Repositories** created:
   ```bash
   aws ecr create-repository --repository-name firstweeks/api --region us-east-1
   aws ecr create-repository --repository-name firstweeks/web --region us-east-1
   ```
2. **Images built and pushed** via GitHub Actions (automatic on merge to main)

### Secrets (AWS Secrets Manager)
Create these secrets manually or via Terraform:
- `production/jwt-secret` - 32+ character random string
- `production/push-vapid-public-key` - VAPID public key
- `production/push-vapid-private-key` - VAPID private key
- `production/database-password` - Auto-generated by Terraform (RDS)

### GitHub Actions OIDC
1. **IAM Role** for GitHub Actions (created by Terraform `security` module)
2. **GitHub Environment** `production` with required reviewers
3. **GitHub Secrets**:
   - `AWS_GITHUB_ACTIONS_ROLE_ARN` - Role ARN from Terraform output

## Deployment Steps

### 1. Initial Setup (One-time)
```bash
cd infra/terraform/environments/production

# Copy and edit variables
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars with real values

# Initialize with S3 backend
terraform init -backend-config="bucket=firstweeks-terraform-state" \
                -backend-config="key=production/terraform.tfstate" \
                -backend-config="region=us-east-1" \
                -backend-config="encrypt=true" \
                -backend-config="dynamodb_table=terraform-locks"
```

### 2. Plan & Review
```bash
terraform plan -out=tfplan
# Review plan carefully - check for:
# - Resource counts match expectations
# - No unexpected deletions
# - Sensitive values not exposed in plan output
```

### 3. Apply
```bash
terraform apply tfplan
# Or for interactive:
terraform apply
```

### 4. Post-Deployment Verification
```bash
# Get outputs
terraform output

# Verify ALB health
curl -f https://$(terraform output -raw alb_dns_name)/healthz

# Verify API
curl -f https://$(terraform output -raw alb_dns_name)/api/healthz

# Verify Database connectivity
aws rds describe-db-instances --db-instance-identifier $(terraform output -raw db_instance_id) --query 'DBInstances[0].Endpoint.Address'
```

## CI/CD Pipeline

### Automatic Deployment (on merge to main)
1. GitHub Actions runs: lint → typecheck → test:unit → build → test:integration → test:e2e
2. On success: Build Docker images → Push to ECR → Deploy to staging
3. **Manual approval required** for production promotion

### Manual Production Promotion
1. Go to GitHub Actions → "Deploy to Production" workflow
2. Click "Run workflow" → Select `main` branch → Confirm
3. Workflow:
   - Pulls latest images from GHCR
   - Tags and pushes to ECR
   - Updates ECS services (rolling deployment)
   - Waits for service stability
   - Runs smoke tests

### Rollback
```bash
# Option 1: GitHub Actions - Re-run previous successful production deployment
# Option 2: ECS Console - Update service to previous task definition
# Option 3: Terraform - Revert to previous state (last resort)
```

## Backup & Disaster Recovery

### RDS
- Automated backups: 35-day retention (production)
- Point-in-time recovery: Enabled
- Multi-AZ: Enabled
- Cross-region replica: Consider for DR

### S3
- Versioning enabled
- Cross-region replication: Configure for analytics bucket

### Terraform State
- S3 versioning + DynamoDB locking
- Regular state file backups

### RTO/RPO Targets
- **RPO**: < 1 hour (RDS point-in-time recovery)
- **RTO**: < 4 hours (ECS + RDS failover)

## Troubleshooting

### Common Issues

**ECS Tasks Not Starting**
```bash
# Check service events
aws ecs describe-services --cluster production-firstweeks --services production-firstweeks-api

# Check task logs
aws logs get-log-events --log-group-name /ecs/production-firstweeks-api --log-stream-name <stream-name>
```

**ALB Health Checks Failing**
```bash
# Check target group health
aws elbv2 describe-target-health --target-group-arn <target-group-arn>

# Verify security groups allow ALB -> ECS on port 8080
```

**Database Connection Issues**
```bash
# Verify RDS endpoint
aws rds describe-db-instances --db-instance-identifier <db-id>

# Check security group allows ECS SG on port 5432
```

**Certificate Issues**
```bash
# Verify ACM certificate status
aws acm describe-certificate --certificate-arn <cert-arn> --region us-east-1
```

## Cost Optimization

### Monthly Estimates (Production)
| Service | Estimated Cost |
|---------|----------------|
| ECS Fargate (2 tasks + ALB) | $300-500 |
| RDS PostgreSQL Multi-AZ (db.t3.medium) | $200-400 |
| S3 + CloudFront + Data Transfer | $50-100 |
| Secrets Manager + KMS | $20-40 |
| CloudWatch + Grafana Cloud Pro | $100-200 |
| SendGrid (email) | $50 |
| Route 53 + ACM | $15 |
| **Total** | **~$735-1,305/month** |

### Cost Savings
- Use Fargate Spot for non-critical workloads
- Right-size instances based on actual usage
- Enable S3 Intelligent-Tiering
- Review CloudWatch log retention
