# Firstweeks Production Deployment Runbook

## Overview
This runbook covers deploying Firstweeks to production (AWS with HIPAA BAA) and managing the pilot launch with 2 OB-GYN practices.

## Prerequisites

### AWS Account Setup
- [ ] AWS account with HIPAA BAA signed
- [ ] AWS CLI configured with appropriate permissions
- [ ] Terraform >= 1.5 installed
- [ ] Domain registered (firstweeks.app) with Route 53 hosted zone
- [ ] ACM certificate for `*.firstweeks.app` in us-east-1

### Vendor BAAs (Must be signed before production deploy)
- [ ] AWS (covers RDS, ECS, S3, CloudWatch, Secrets Manager, KMS, ALB, WAF)
- [ ] SendGrid (transactional email)
- [ ] Twilio (SMS, if enabled)
- [ ] Grafana Cloud (monitoring)
- [ ] Any other sub-processors

### Secrets Preparation (Store in AWS Secrets Manager)
```
production/jwt-secret              # 64-char random string
production/database-url            # Auto-generated by Terraform
production/jwt-access-ttl          # "15m"
production/jwt-refresh-ttl         # "7d"
production/push-vapid-public-key   # From `npx web-push generate-vapid-keys`
production/push-vapid-private-key  # From `npx web-push generate-vapid-keys`
production/push-vapid-subject      # "mailto:admin@firstweeks.app"
```

### GitHub Repository Secrets
- [ ] `AWS_GITHUB_ACTIONS_ROLE_ARN` - OIDC role for GitHub Actions
- [ ] `OCI_CONFIG` / `OCI_PRIVATE_KEY` - For Oracle Cloud staging (if still used)

## Deployment Procedures

### 1. Initial Production Infrastructure Deployment

```bash
# 1. Navigate to Terraform production environment
cd infra/terraform/environments/production

# 2. Create terraform.tfvars from example
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars with your values:
# - region = "us-east-1"
# - github_repo = "your-org/firstweeks"
# - certificate_arn = "arn:aws:acm:us-east-1:xxxx:certificate/xxx"
# - alarm_email = "alerts@firstweeks.app"
# - api_image = "ghcr.io/your-org/firstweeks/api:latest"
# - web_image = "ghcr.io/your-org/firstweeks/web:latest"
# - jwt_secret = "<from-secrets-manager>"
# - push_vapid_public_key = "<from-secrets-manager>"
# - push_vapid_private_key = "<from-secrets-manager>"

# 3. Initialize Terraform with remote state
terraform init -backend-config=backend.hcl

# 4. Plan and review
terraform plan

# 5. Apply (requires approval)
terraform apply

# 6. Verify outputs
terraform output alb_dns_name
terraform output database_endpoint
terraform output github_actions_role_arn
```

### 2. Configure GitHub Actions OIDC

```bash
# Get the role ARN from Terraform output
ROLE_ARN=$(terraform output -raw github_actions_role_arn)

# In GitHub repo settings > Secrets > Actions, add:
# AWS_GITHUB_ACTIONS_ROLE_ARN = <ROLE_ARN>
```

### 3. Seed Production Database

```bash
# After infrastructure is up, run migrations and seed
# Option A: Via GitHub Actions (recommended)
# - Push to main branch triggers deploy-staging
# - Manual promotion to production runs migrations

# Option B: Local with production DATABASE_URL
export DATABASE_URL=$(aws secretsmanager get-secret-value \
  --secret-id production/database-url \
  --query SecretString --output text | jq -r .url)

pnpm db:migrate:deploy
pnpm db:seed
```

### 4. Create Pilot Clinician Accounts

```bash
# Run the clinician seeding script
pnpm --filter=@firstweeks/api tsx scripts/seed-clinicians.ts
```

### 5. Verify Deployment

```bash
# Health checks
curl -f https://app.firstweeks.app/healthz
curl -f https://api.firstweeks.app/healthz

# API docs
open https://api.firstweeks.app/docs

# Check logs
aws logs tail /aws/ecs/production/api --follow
aws logs tail /aws/ecs/production/web --follow
```

## Operational Procedures

### Daily Operations (During Pilot)

#### Morning Check (9 AM)
```bash
# 1. Check Grafana dashboard
open https://grafana.firstweeks.app/d/pilot-overview

# 2. Review automated Slack report (sent at 9:30 AM)
# - DAU / WAU / MAU
# - Check-in completion rate
# - New escalations (last 24h)
# - Referral conversions
# - Error rate / latency

# 3. Check for critical alerts
aws cloudwatch describe-alarms --alarm-names production-api-high-cpu production-rds-high-cpu
```

#### Escalation Triage (As Needed)
```bash
# 1. Review escalation queue
curl -H "Authorization: Bearer <CLINICIAN_TOKEN>" \
  https://api.firstweeks.app/api/clinician/escalations

# 2. Triage: Update status to TRIAGED
curl -X PATCH -H "Authorization: Bearer <CLINICIAN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"status": "TRIAGED", "assignedTo": "<clinician-id>"}' \
  https://api.firstweeks.app/api/clinician/escalations/<escalation-id>

# 3. Create referral if warranted
curl -X POST -H "Authorization: Bearer <CLINICIAN_TOKEN>" \
  https://api.firstweeks.app/api/escalations/<escalation-id>/referral
```

### Incident Response

#### Severity Levels
| Level | Definition | Response Time | Escalation |
|-------|------------|---------------|------------|
| SEV-1 | Service down, data loss, PHI breach | 15 min | CTO + CEO + Legal |
| SEV-2 | Major feature broken, high error rate | 1 hour | CTO + On-call |
| SEV-3 | Minor bug, degraded performance | 4 hours | On-call |
| SEV-4 | Cosmetic, low impact | Next sprint | Team |

#### SEV-1 Response Playbook
1. **Acknowledge** in Slack #incidents within 15 min
2. **Assess** impact: API down? Database? PHI exposed?
3. **Mitigate**: Rollback deployment, scale up, failover
4. **Communicate**: Status page, practices notified if patient-facing
5. **Resolve**: Fix root cause, deploy fix
6. **Postmortem**: Within 48 hours, blameless

#### Rollback Procedure
```bash
# Quick rollback via ECS (previous task definition)
aws ecs update-service \
  --cluster production-firstweeks \
  --service production-firstweeks-api \
  --task-definition production-firstweeks-api:<PREVIOUS_REVISION> \
  --force-new-deployment

# Or via GitHub Actions: Re-run previous successful deploy-production workflow
```

### Database Operations

#### Backup Verification (Weekly)
```bash
# Check latest automated backup
aws rds describe-db-snapshots \
  --db-instance-identifier production-firstweeks-db \
  --snapshot-type automated \
  --query 'DBSnapshots[0].SnapshotCreateTime'

  --source-db-instance-identifier production-firstweeks-db \
  --target-db-instance-identifier production-firstweeks-db-pitr-test \
  --restore-time 2026-10-01T12:00:00Z
```

### Critical Alerts (PagerDuty/On-call)
- `production-api-high-cpu` > 80% for 2 periods
- `production-api-high-memory` > 80% for 2 periods
- `production-alb-5xx-errors` > 10/min
- `production-alb-high-latency` > 1s for 2 periods
- `production-rds-high-cpu` > 80% for 2 periods
- `production-rds-low-storage` < 10GB
- `production-api-unhealthy-tasks` < 2 running
- `production-web-unhealthy-tasks` < 2 running

### Log Queries (CloudWatch Insights)
```sql
-- Recent errors
fields @timestamp, @message
| filter @message like /ERROR/
| sort @timestamp desc
| limit 100

-- Slow API requests (>1s)
fields @timestamp, @requestId, @duration, @status
| filter @duration > 1000
| sort @duration desc
| limit 50

-- Escalation events
fields @timestamp, @message
| filter @message like /ESCALATION/
| sort @timestamp desc
| limit 50
```

## Security Procedures

### Secret Rotation (Quarterly)
```bash
# Rotate JWT secret
NEW_JWT_SECRET=$(openssl rand -base64 48)
aws secretsmanager put-secret-value \
  --secret-id production/jwt-secret \
  --secret-string "$NEW_JWT_SECRET"

# Trigger rolling restart
aws ecs update-service --cluster production-firstweeks \
  --service production-firstweeks-api --force-new-deployment
```

### Vulnerability Scanning
- Trivy runs on every build (CI)
- npm audit on every PR
- Dependabot PRs weekly
- Semgrep on every PR
- TruffleHog on every push

### Access Review (Monthly)
- Review IAM roles/policies
- Check Secrets Manager access
- Verify S3 bucket policies
- Audit CloudTrail for unusual activity

## Cost Monitoring

### Monthly Budget Alerts
```bash
# Set up billing alarm at $1,500/month
aws cloudwatch put-metric-alarm \
  --alarm-name "Monthly-Cost-Alert" \
  --metric-name "EstimatedCharges" \
  --namespace "AWS/Billing" \
  --statistic Maximum \
  --period 86400 \
  --threshold 1500 \
  --comparison-operator GreaterThanThreshold \
  --evaluation-periods 1
```

### Cost Optimization

- RDS instance right-sizing (review monthly)
- S3 Intelligent Tiering for analytics bucket
